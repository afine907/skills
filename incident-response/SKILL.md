# Incident Response — 应急响应技能

提供结构化事故处理流程，从发现到复盘全链路支持。


## Goal

结构化事故处理流程，包含事故分级、应急处置、根因分析(RCA)、复盘报告生成

## Trigger

- 生产环境出现故障需要应急处理
  - 用户要求"写RCA"、"事故复盘"、"故障分析"
  - 需要制定应急预案

## 事故分级

| 级别 | 名称 | 影响范围 | 响应时间 | 示例 |
|------|------|----------|----------|------|
| P0 | 严重 | 核心服务完全不可用 | 5分钟 | 全站宕机、数据丢失 |
| P1 | 紧急 | 核心功能降级 | 15分钟 | 支付失败率>50%、登录不可用 |
| P2 | 重要 | 非核心功能异常 | 1小时 | 搜索慢、报表延迟 |
| P3 | 一般 | 体验问题 | 4小时 | UI 显示异常、非关键 API 慢 |
| P4 | 轻微 | 微小问题 | 下个迭代 | 文案错误、日志格式问题 |

## 应急处理流程

### Phase 1: 发现与确认 (0-5min)

```
1. 确认问题真实性（排除误报）
2. 评估影响范围和严重程度
3. 确定事故等级（P0-P4）
4. 启动对应级别的响应流程
```

### Phase 2: 应急处置 (5-30min)

**优先级：止血 > 恢复 > 查因**

```
止血手段（按优先级）：
1. 回滚最近的发布
2. 切换到备用系统/降级方案
3. 扩容（如果是因为流量）
4. 重启服务（如果是个例）
5. 关闭问题功能（功能开关）
```

### Phase 3: 根因分析 (30min-2h)

```
1. 收集证据（日志、指标、链路追踪）
2. 确定触发条件
3. 定位根本原因
4. 制定修复方案
```

### Phase 4: 修复与验证 (2h-24h)

```
1. 实施修复方案
2. 验证修复效果
3. 监控是否有副作用
4. 确认恢复正常
```

### Phase 5: 复盘 (24h-72h)

```
1. 撰写 RCA 报告
2. 召开复盘会议
3. 制定改进措施
4. 跟踪改进落实
```
