# Agent 代码执行安全审计清单

> 版本：1.0 | 适用范围：具备代码执行能力的 AI Agent 系统（类似 Code Interpreter）

---

## 一、执行环境隔离

### 1.1 沙箱隔离

- [ ] 每次代码执行在独立的沙箱容器（如 gVisor / Firecracker microVM）中运行，禁止直接使用宿主机环境。
- [ ] 沙箱生命周期与单次执行绑定，执行结束后销毁，不留持久状态（除非明确设计需要）。
- [ ] 沙箱之间互相隔离，不同用户 / 会话的执行环境不可互相访问。
- [ ] 沙箱镜像为最小化基础镜像（distroless / alpine），不包含调试工具、编译器等非必要组件。

### 1.2 容器与虚拟化安全

- [ ] 容器以非 root 用户运行（UID > 0），禁止 `privileged` 模式。
- [ ] 启用 seccomp 筧略，仅允许执行所需的最小系统调用集合。
- [ ] 启用 AppArmor / SELinux 强制访问控制策略。
- [ ] 禁用容器内的 `ptrace`、`mount`、`reboot` 等危险系统调用。
- [ ] cgroup 资源限制已配置（CPU、内存、PID 数量、文件描述符数量）。

### 1.3 网络隔离

- [ ] 默认禁止沙箱内所有出站网络访问（deny-all egress policy）。
- [ ] 如需网络访问，通过显式白名单开放特定域名 / IP + 端口，且需经过审批。
- [ ] 禁止沙箱之间互相通信（无东西向流量）。
- [ ] 所有允许的出站流量经过代理网关，记录完整访问日志。

## 二、代码执行控制

### 2.1 输入验证与过滤

- [ ] 对用户输入的代码进行预处理，移除或转义可能导致注入的特殊字符。
- [ ] 检测并拒绝已知的恶意代码模式（如反弹 shell、加密矿机、数据外泄脚本）。
- [ ] 对代码长度、复杂度设置上限（行数、字符数、AST 节点数）。
- [ ] 使用静态分析工具（如 Semgrep / Bandit / ESLint-security）对提交代码进行扫描，阻断高危模式。

### 2.2 执行权限最小化

- [ ] 执行用户仅拥有运行所需的最小文件系统权限（只读挂载系统目录，可写仅限临时工作区）。
- [ ] 禁止访问宿主机的 Docker socket、Kubernetes API、cloud metadata endpoint（169.254.169.254）。
- [ ] 禁止加载内核模块、修改系统配置（sysctl、iptables 等）。
- [ ] 禁止创建特权文件（SUID/SGID）、修改 `/etc/passwd`、`/etc/shadow` 等。

### 2.3 资源限制

- [ ] 单次执行最大 CPU 时间限制（如 30 秒 wall time / 10 秒 CPU time）。
- [ ] 单次执行最大内存使用限制（如 512MB）。
- [ ] 磁盘写入限制（如 100MB 临时空间）。
- [ ] 最大输出长度限制（stdout/stderr 截断，防止通过输出耗尽内存）。
- [ ] 禁止 fork bomb：限制进程 / 线程数量上限（如 PID_MAX=64）。

### 2.4 执行超时与中断

- [ ] 设置硬超时机制，超时后强制 kill 执行进程及其所有子进程（kill process group）。
- [ ] 支持管理员手动中断正在执行的代码。
- [ ] 检测并终止死循环模式（如 CPU 持续占用超过阈值且无 I/O）。

---

## 三、数据安全

### 3.1 敏感数据保护

- [ ] 执行环境无法访问任何 API Key、数据库密码、证书等密钥材料。
- [ ] 用户数据在不同会话之间严格隔离，执行完毕后临时存储立即清除。
- [ ] 禁止通过代码执行访问 Agent 自身的系统提示词（system prompt）和内部配置。
- [ ] 输出内容经过脱敏处理，自动检测并遮蔽出现的 PII（身份证号、手机号、邮箱等）。

### 3.2 文件系统安全

- [ ] 工作目录为临时目录（`/tmp` 或 tmpfs），与宿主机文件系统完全隔离。
- [ ] 禁止挂载宿主机敏感路径（`/etc`、`/var/run`、`~/.ssh`、`~/.aws` 等）。
- [ ] 文件系统以 `noexec` 方式挂载（防止在可写目录执行二进制文件）。
- [ ] 用户上传的文件经过杀毒扫描和格式验证后再挂载到沙箱。

### 3.3 数据外泄防护

- [ ] 监控并限制单次执行的数据传输量（出站字节数上限）。
- [ ] 检测常见的数据外泄模式（DNS 隧道、HTTP 编码外传、隐写术）。
- [ ] 禁止通过环境变量、进程列表等侧信道泄露宿主机信息。
- [ ] 用户上传的文件在执行结束后销毁，不跨会话保留。

---

## 四、依赖与供应链安全

### 4.1 包管理控制

- [ ] 代码执行环境中预装的依赖包经过安全审计，版本锁定。
- [ ] 禁止在执行过程中动态安装新的依赖包（`pip install`、`npm install` 等），或仅允许从私有镜像源安装已审批的白名单包。
- [ ] 如允许动态安装，必须对包名进行 typosquatting 检测。
- [ ] 定期扫描沙箱镜像中的依赖漏洞（Trivy / Snyk / Grype）。

### 4.2 运行时完整性

- [ ] 沙箱镜像使用签名验证（cosign / Notary），防止篡改。
- [ ] 执行二进制文件的完整性校验（hash verification）。
- [ ] 禁止在运行时修改沙箱内的系统文件和已安装的依赖。

---

## 五、审计与监控

### 5.1 日志记录

- [ ] 每次代码执行记录完整审计日志：用户 ID、会话 ID、提交的代码、执行结果、资源消耗、执行时长。
- [ ] 所有系统调用通过 auditd / eBPF 进行记录。
- [ ] 网络连接日志记录所有出站请求的目标、端口、协议、数据量。
- [ ] 日志不可被沙箱内代码篡改或删除，实时推送到中心化日志系统。

### 5.2 异常检测

- [ ] 部署运行时异常行为检测（如异常系统调用序列、异常网络行为、异常文件操作）。
- [ ] 设置告警规则：资源使用超阈值、访问被拒绝的资源、尝试逃逸行为。
- [ ] 对高频执行请求进行速率限制，防止滥用。
- [ ] 检测并告警重复的恶意尝试模式（同一用户反复尝试绕过限制）。

### 5.3 合规审计

- [ ] 所有审计日志保留期限满足合规要求（如 90 天）。
- [ ] 支持按用户、时间、行为类型检索审计记录。
- [ ] 定期（至少每季度）生成安全审计报告，覆盖执行次数、异常事件、阻断统计。

## 六、Agent 自身安全

### 6.1 提示词防护

- [ ] Agent 系统提示词中明确定义代码执行的边界和禁止行为。
- [ ] 防范提示词注入攻击：用户输入与系统指令严格分离，代码内容不作为指令解析。
- [ ] Agent 不会将用户的自然语言指令直接拼接为可执行代码（需经过安全校验层）。
- [ ] 防范间接提示词注入：从外部数据源（网页、文件、API 响应）获取的内容不作为指令执行。

### 6.2 权限边界

- [ ] Agent 执行代码的能力需经过显式授权（用户确认或管理员配置），不可自动静默执行。
- [ ] 高风险操作（如访问网络、读写文件、调用外部 API）需额外确认步骤。
- [ ] Agent 无法通过代码执行提升自身权限或修改自身运行配置。
- [ ] Agent 无法通过代码执行绕过其自身的安全限制（如删除安全检查中间件）。

### 6.3 多轮对话安全

- [ ] 跨轮次的状态不累积权限——每轮代码执行独立评估安全策略。
- [ ] 历史执行结果不自动注入后续执行的代码中（防止通过多轮逐步构造恶意代码）。
- [ ] 长对话场景下，安全上下文不因窗口截断而丢失。

## 七、应急响应

### 7.1 事件响应流程

- [ ] 制定代码执行安全事件分级标准（P0-P3）及对应的响应 SLA。
- [ ] 明确安全事件的上报、调查、处置、复盘流程。
- [ ] 建立应急响应 on-call 机制，确保 P0 事件 15 分钟内响应。

### 7.2 遏制与恢复

- [ ] 支持一键禁用所有用户的代码执行能力（紧急开关 / kill switch）。
- [ ] 支持按用户粒度封禁代码执行权限。
- [ ] 发现逃逸行为时，自动销毁受影响的沙箱并隔离相关用户。
- [ ] 制定沙箱逃逸场景的专项应急预案。

### 7.3 漏洞管理

- [ ] 建立沙箱逃逸漏洞的赏金计划或内部红队测试机制。
- [ ] 关键安全组件（内核、容器运行时、沙箱引擎）的补丁更新 SLA：关键漏洞 24 小时，高危漏洞 7 天。
- [ ] 定期（至少每半年）进行一次针对代码执行环境的渗透测试。

## 九、风险评估矩阵

| 风险类别 | 威胁描述 | 影响等级 | 可能性 | 缓解措施 |
|----------|---------|---------|--------|---------|
| 沙箱逃逸 | 攻击者利用容器 / 内核漏洞逃逸到宿主机 | 严重 | 低 | 最小化镜像、seccomp、内核补丁及时更新 |
| 数据外泄 | 通过代码执行将用户数据发送到外部 | 高 | 中 | 网络隔离、出站流量监控、数据量限制 |
| 资源耗尽 | 恶意代码消耗大量计算资源导致 DoS | 高 | 中 | cgroup 限制、超时机制、速率限制 |
| 提示词注入 | 通过代码或数据注入恶意指令控制 Agent | 高 | 中 | 输入分离、输出过滤、行为约束 |
| 供应链攻击 | 预装依赖被投毒或 typosquatting | 中 | 中 | 镜像签名、版本锁定、私有镜像源 |
| 横向移动 | 通过一个会话访问其他用户数据 | 高 | 低 | 会话隔离、沙箱销毁策略 |
| 加密矿机 | 在沙箱内运行挖矿代码 | 中 | 中 | CPU 限制、网络隔离、行为检测 |
| 反弹 Shell | 获取交互式 shell 访问 | 严重 | 低 | 网络隔离、系统调用过滤、进程监控 |

## 十、参考标准与框架

- **NIST SP 800-53** — 系统与通信保护（SC）、访问控制（AC）、审计与问责（AU）
- **OWASP LLM Top 10 (2025)** — LLM05: Improper Output Handling, LLM06: Excessive Agency
- **CIS Docker Benchmark** — 容器安全配置基线
- **MITRE ATT&CK — Containers** (T1610-T1613) — 容器逃逸与攻击技术分类
- **ISO 27001:2022** — A.8 安全控制，特别是 A.8.28 安全编码

## 附录 B：安全测试用例示例

### B.1 逃逸测试

```python
# 测试：尝试访问宿主机文件系统
import os
assert not os.path.exists('/host'), "沙箱应无法访问宿主机根目录"
assert not os.path.exists('/var/run/docker.sock'), "沙箱应无法访问 Docker socket"

# 测试：尝试访问 cloud metadata
import urllib.request
try:
    urllib.request.urlopen('http://169.254.169.254/latest/meta-data/', timeout=3)
    assert False, "沙箱不应能访问 cloud metadata"
except Exception:
    pass  # 预期行为：连接被拒绝
```

### B.2 资源限制测试

```python
# 测试：内存限制
try:
    bytearray(1024 * 1024 * 1024)  # 尝试分配 1GB
    assert False, "应触发内存限制"
except MemoryError:
    pass  # 预期行为

# 测试：进程数量限制
import subprocess
try:
    for _ in range(200):
        subprocess.Popen(['sleep', '100'])
    assert False, "应触发进程数限制"
except OSError:
    pass  # 预期行为
```

### B.3 数据隔离测试

```python
# 测试：无法读取其他会话的数据
import os
for path in ['/data/other-session', '/home/other-user']:
    assert not os.path.exists(path), f"不应存在路径: {path}"

# 测试：环境变量不包含敏感信息
import os
for key in os.environ:
    lower_key = key.lower()
    assert 'key' not in lower_key or 'api' not in lower_key, f"环境变量 {key} 可能包含敏感信息"
    assert 'secret' not in lower_key, f"环境变量 {key} 可能包含敏感信息"
    assert 'password' not in lower_key, f"环境变量 {key} 可能包含敏感信息"
```
