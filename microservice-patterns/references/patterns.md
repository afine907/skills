# 微服务设计模式参考

## 服务通信模式

### 同步通信

#### 请求-响应模式
```
客户端 ──HTTP/gRPC──▶ 服务端
       ◀──Response──
```

**适用场景**：查询数据、提交表单
**优点**：简单、实时
**缺点**：服务间强耦合

#### API 网关模式
```
客户端 ──▶ API 网关 ──▶ 服务A
                  ├────▶ 服务B
                  └────▶ 服务C
```

**优点**：统一入口、认证、限流
**实现**：Kong、Nginx、AWS API Gateway

### 异步通信

#### 事件驱动模式
```
服务A ──Publish──▶ 事件总线 ──Subscribe──▶ 服务B
                                    └──────▶ 服务C
```

**优点**：解耦、可扩展
**实现**：Kafka、RabbitMQ、AWS SNS

#### 命令队列模式
```
服务A ──Command──▶ 队列 ──Consume──▶ 服务B
```

**优点**：削峰填谷、异步处理
**实现**：RabbitMQ、AWS SQS

## 数据管理模式

### 每服务一数据库
```
服务A ──▶ 数据库A
服务B ──▶ 数据库B
服务C ──▶ 数据库C
```

**优点**：松耦合、独立演进
**缺点**：跨服务查询复杂

### Saga 模式（分布式事务）

#### 协调式 Saga
```
订单服务 ──▶ 库存服务 ──▶ 支付服务
    │           │           │
    └──补偿─────┴──补偿─────┘
```

#### 编排式 Saga
```
Saga 编排器 ──▶ 订单服务
      ├──────▶ 库存服务
      └──────▶ 支付服务
```

### CQRS 模式（命令查询分离）
```
写操作 ──▶ 命令服务 ──▶ 写数据库
                       │
                       ▼ 同步/异步
读操作 ──▶ 查询服务 ──▶ 读数据库
```

## 服务发现模式

### 客户端发现
```
客户端 ──查询──▶ 服务注册表
      ──请求──▶ 服务实例
```

### 服务端发现
```
客户端 ──请求──▶ 负载均衡器 ──查询──▶ 服务注册表
                            ──转发──▶ 服务实例
```

**实现**：Consul、Eureka、Nacos、etcd

## 弹性模式

### 熔断器模式
```
关闭状态 ──失败超阈值──▶ 打开状态 ──超时──▶ 半开状态
    ▲                                        │
    └──────────成功──────────────────────────┘
```

### 重试模式
```
请求 ──失败──▶ 等待 ──重试──▶ 成功
                    │
                    └──超过次数──▶ 失败
```

### 舱壁模式
```
服务A ──▶ 连接池1 ──▶ 服务X
服务B ──▶ 连接池2 ──▶ 服务X
服务C ──▶ 连接池3 ──▶ 服务X
```

## 部署模式

### 蓝绿部署
```
当前版本（蓝）◀──流量──负载均衡器
新版本（绿）  ──空闲──
```

### 金丝雀发布
```
90% 流量 ──▶ 当前版本
10% 流量 ──▶ 新版本（金丝雀）
```

### 滚动更新
```
实例1 ──更新──▶ 新版本
实例2 ──更新──▶ 新版本
实例3 ──更新──▶ 新版本
```
