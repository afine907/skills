# 幻觉模式与检测启发式

## 常见幻觉类型

### 类型 1：事实编造

**症状：** Agent 编造不存在的事实、数据、引用

| 模式 | 示例 | 检测方法 |
|------|------|---------|
| 编造引用 | "根据2024年XX研究..."（该研究不存在） | 验证引用来源是否存在 |
| 编造数据 | "市场份额为23.5%"（无数据来源） | 检查上下文中是否有数据来源 |
| 编造URL | "详见 https://example.com/report"（链接不存在） | 验证URL可访问 |
| 编造人物 | "正如张教授所说..."（无此人） | 验证人物身份 |

### 类型 2：推理幻觉

**症状：** Agent 在推理过程中引入了不存在的前提或错误的逻辑

| 模式 | 示例 | 检测方法 |
|------|------|---------|
| 错误前提 | "因为A是B，所以C是D"（A不是B） | 验证推理链中每个前提 |
| 过度推断 | "用户说喜欢蓝色，所以一定喜欢海洋" | 检查推断是否有充分依据 |
| 因果错误 | "因为X发生了，所以Y一定是X导致的" | 检查因果关系是否成立 |

### 类型 3：上下文幻觉

**症状：** Agent 歪曲或编造了之前对话中的内容

| 模式 | 示例 | 检测方法 |
|------|------|---------|
| 引用错误 | "您之前说过..."（用户没说过） | 比对实际对话历史 |
| 篡改内容 | "您要求的是A"（实际要求的是B） | 比对实际输入 |
| 遗忘关键信息 | 忽略了用户明确提供的约束 | 检查是否遗漏关键输入 |

### 类型 4：工具幻觉

**症状：** Agent 声称调用了工具或获得了结果，但实际没有

| 模式 | 示例 | 检测方法 |
|------|------|---------|
| 伪造工具调用 | "根据搜索结果..."（未实际搜索） | 验证工具调用日志 |
| 伪造工具结果 | "API返回了..."（实际返回不同） | 比对实际工具输出 |
| 忽略工具错误 | 工具报错但 Agent 仍使用"结果" | 检查错误处理日志 |

## 检测启发式规则

### 规则 1：溯源验证

```
对输出中的每个事实陈述:
  if 可从上下文中找到直接依据:
    标记为 "可溯源"
  elif 可从上下文中合理推断:
    标记为 "合理推断"
  else:
    标记为 "幻觉嫌疑"
```

### 规则 2：确定性检查

```
对输出中的每个断言:
  if 使用了确定性语言（"是"、"一定是"、"肯定是"）:
    if 断言无法从上下文中验证:
      标记为 "过度自信幻觉"
  elif 使用了不确定性语言（"可能"、"也许"、"我不确定"）:
    if 断言实际上是可验证的:
      标记为 "不必要的不确定性"
```

### 规则 3：一致性检查

```
对输出中的每对陈述:
  if 两个陈述存在逻辑矛盾:
    标记为 "内部不一致"
  if 陈述与之前的对话历史矛盾:
    标记为 "上下文不一致"
```

### 规则 4：细节丰富度检查

```
对输出中的具体细节:
  if 包含具体数字但上下文中无数据来源:
    高幻觉风险
  if 包含具体引用但无法验证:
    高幻觉风险
  if 细节过于完美（精确到小数点后多位）:
    中等幻觉风险（可能编造）
```

## 自动化检测提示模板

### 幻觉扫描提示

```
请分析以下 Agent 输出中的每个事实陈述，判断其可信度：

Agent 输出：
{output}

提供的上下文：
{context}

对每个事实陈述，输出：
1. 陈述内容
2. 分类：可溯源 / 合理推断 / 无法验证 / 明确错误
3. 依据（如果可溯源，引用上下文中的具体内容）
4. 风险等级：低 / 中 / 高

最后给出整体幻觉风险评分（0-10，10为无幻觉风险）。
```

### 工具幻觉检测提示

```
请比对以下工具调用日志和 Agent 输出，检查是否存在工具幻觉：

工具调用日志：
{tool_logs}

Agent 输出：
{output}

检查：
1. Agent 声称调用的工具是否在日志中存在？
2. Agent 声称获得的结果是否与日志中的实际结果一致？
3. 工具报错时，Agent 是否正确处理了错误？

对每个发现，输出：幻觉类型、具体内容、严重程度。
```
