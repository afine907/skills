# User Story — 用户故事编写技能

将业务需求拆解为可执行的用户故事，附带验收标准和估算。

## 工作流程

```
业务需求 → 角色识别 → 故事拆分 → 验收标准 → 估算 → 排序
```

## 用户故事格式

### 标准格式

```
作为 {角色}，
我希望 {功能/行为}，
以便 {价值/收益}。
```

### 完整故事卡片

```markdown
## US-{编号}: {故事标题}

**作为** {角色}  
**我希望** {功能描述}  
**以便** {业务价值}

### 验收标准 (Acceptance Criteria)

**场景 1: 成功路径**
- Given {前置条件}
- When {操作}
- Then {期望结果}

**场景 2: 边界条件**
- Given {边界前置条件}
- When {边界操作}
- Then {边界期望}

**场景 3: 异常路径**
- Given {异常前置条件}
- When {异常操作}
- Then {错误处理}

### 故事点: {1/2/3/5/8/13}
### 优先级: {P0/P1/P2}
### 标签: {功能模块, 技术类型}

### 备注
- {技术约束}
- {依赖其他故事}
- {设计参考}
```

## 故事拆分原则

### INVEST 原则

| 原则 | 含义 | 检查 |
|------|------|------|
| **I**ndependent | 故事间无强依赖 | 能独立开发测试吗？ |
| **N**egotiable | 可协商的，非合同 | 有讨论空间吗？ |
| **V**aluable | 对用户有价值 | 用户能感知到吗？ |
| **E**stimable | 可估算的 | 能给出故事点吗？ |
| **S**mall | 足够小，一个 Sprint 能完成 | 能在1-3天内完成吗？ |
| **T**estable | 可测试的 | 有明确的验收标准吗？ |

### 拆分策略

| 策略 | 示例 |
|------|------|
| 按操作拆分 | CRUD → 每个操作一个故事 |
| 按数据拆分 | 支持多种数据类型 → 每种一个故事 |
| 按规则拆分 | 复杂业务规则 → 每条规则一个故事 |
| 按场景拆分 | 多种用户场景 → 每个场景一个故事 |
| 按层级拆分 | 端到端 → 前端/后端/数据层 |

### 故事点估算

| 点数 | 复杂度 | 说明 |
|------|--------|------|
| 1 | 极小 | 简单配置修改 |
| 2 | 小 | 简单 CRUD |
| 3 | 中 | 中等复杂度业务逻辑 |
| 5 | 大 | 复杂业务逻辑 + 多模块交互 |
| 8 | 很大 | 需要技术调研的复杂功能 |
| 13 | 超大 | 需要拆分为多个故事 |

## 输出示例

```markdown
## US-001: 用户注册

**作为** 新用户  
**我希望** 通过邮箱注册账号  
**以便** 使用平台的核心功能

### 验收标准

**场景 1: 成功注册**
- Given 用户打开注册页面
- When 输入有效邮箱、符合要求的密码、点击注册
- Then 账号创建成功，收到验证邮件，跳转到登录页

**场景 2: 邮箱已存在**
- Given 用户打开注册页面
- When 输入已注册的邮箱、点击注册
- Then 提示"该邮箱已注册"，建议直接登录

**场景 3: 密码不符合要求**
- Given 用户打开注册页面
- When 输入少于8位的密码
- Then 实时提示"密码长度不少于8位"

**场景 4: 邮箱格式错误**
- Given 用户打开注册页面
- When 输入无效邮箱格式
- Then 实时提示"请输入有效的邮箱地址"

### 故事点: 3
### 优先级: P0
### 标签: 用户模块, 认证
```
