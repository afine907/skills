# 工具失败模式目录

## 失败阶段模型

工具调用有 4 个独立的失败阶段，每个阶段需要不同的诊断和修复策略：

```
选择工具 → 构建参数 → 执行调用 → 解析输出
```

### 阶段 1：工具选择失败

**症状：** Agent 选错工具、不选工具、或选了多个不相关的工具

| 失败模式 | 原因 | 检测方式 | 修复策略 |
|---------|------|---------|---------|
| 选错工具 | 工具描述模糊或重叠 | 检查调用日志中工具与任务的匹配度 | 改进工具 description，消除歧义 |
| 不选工具 | 描述未覆盖该场景 | 任务需要工具但 Agent 直接回答 | 补充工具描述中的使用场景 |
| 选择过多 | 未约束调用策略 | 一次调用 3+ 个不相关工具 | 添加工具分组或使用 tool_choice 约束 |

### 阶段 2：参数构建失败

**症状：** Agent 生成了错误格式、缺失必填字段、或幻觉了不存在的参数

| 失败模式 | 原因 | 检测方式 | 修复策略 |
|---------|------|---------|---------|
| 格式错误 | Schema 约束不够严格 | JSON Schema 验证失败 | 添加 enum、format、pattern 约束 |
| 缺失必填 | required 数组不完整 | 验证报错 | 确保 required 声明所有必填参数 |
| 幻觉参数 | 模型凭空编造参数名 | additionalProperties 校验 | 设置 additionalProperties: false |
| 类型错误 | 描述歧义导致类型推断错误 | 类型检查报错 | 在 description 中明确类型和示例 |

### 阶段 3：工具执行失败

**症状：** 工具被正确调用但执行出错

| 失败模式 | 原因 | 检测方式 | 修复策略 |
|---------|------|---------|---------|
| 超时 | 工具响应过慢 | 响应时间 > 阈值 | 设置合理超时 + 重试 |
| 限流 | API 调用频率过高 | HTTP 429 | 指数退避 + 限流队列 |
| 认证失败 | Token 过期或权限不足 | HTTP 401/403 | Token 刷新 + 权限检查 |
| 服务不可用 | 下游服务宕机 | HTTP 5xx | 断路器 + 备用方案 |
| 网络错误 | 连接超时/DNS 失败 | 连接异常 | 重试 + 降级 |

### 阶段 4：输出解析失败

**症状：** 工具返回了数据但 Agent 无法正确理解和使用

| 失败模式 | 原因 | 检测方式 | 修复策略 |
|---------|------|---------|---------|
| Schema 漂移 | API 版本更新导致格式变化 | 输出验证失败 | 版本校验 + 兼容层 |
| 部分响应 | 大响应被截断 | 缺失预期字段 | 标记缺失 + 请求完整数据 |
| 空响应 | 查询无结果 | 返回 null/空数组 | 区分"无结果"和"查询失败" |
| 格式不一致 | 同一工具不同版本返回不同格式 | 类型检查失败 | 统一输出适配层 |

## 恢复策略决策树

```
工具调用失败
├── 瞬时故障？（超时/5xx/限流）
│   ├── 是 → 指数退避重试（最多 3 次）
│   │   ├── 重试成功 → 继续
│   │   └── 重试失败 → 断路器打开 → 降级方案
│   └── 否 ↓
├── 参数错误？（4xx/验证失败）
│   ├── 是 → 返回结构化错误给 LLM → LLM 修正参数重试
│   │   ├── 修正成功 → 继续
│   │   └── 连续 3 次修正失败 → 升级为人工处理
│   └── 否 ↓
├── 工具不可用？（连接拒绝/服务下线）
│   ├── 有备用工具 → 切换备用
│   └── 无备用 → 优雅降级（跳过该步骤 + 标记）
└── 输出异常？（格式不符/数据缺失）
    ├── 可解析 → 标记异常字段 + 使用可用数据
    └── 不可解析 → 请求澄清或换方案
```
