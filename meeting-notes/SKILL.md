# Meeting Notes — 会议纪要生成 Agent

会议文字/录音稿 → 结构化会议纪要。

## 工作流程

```
接收文本 → 识别结构要素 → 生成纪要模板 → 输出
```

## Step 1: 识别会议基本信息

从用户输入中提取或询问：

| 信息 | 说明 |
|------|------|
| **会议主题** | 从文件名或描述中提取，否则询问 |
| **日期** | 从文本中提取或使用当天 |
| **参会人** | 从文本中提取人名或用户提供 |
| **时长** | 可选，从文本中提取 |

**如果输入中不含明确主题**：用 "会议纪要 - <YYYY-MM-DD>" 作为默认标题。

## Step 2: 内容分析

按以下维度分析会议内容：

### 讨论要点
- 提取每个讨论主题及其要点
- 识别争议点和不同意见
- 标注达成共识的部分

### 决策记录
- **Decision**：做出了什么决定
- **Rationale**：决策理由
- **Alternatives considered**：考虑过的其他方案（如有）

### 行动项
| 要素 | 说明 |
|------|------|
| **负责人** | 谁负责 |
| **任务描述** | 做什么 |
| **截止日期** | 什么时候完成 |
| **优先级** | 高/中/低 |

## Step 3: 生成会议纪要

按以下模板输出：

```markdown
# <会议主题>

**日期**: <YYYY-MM-DD>
**参会人**: <名单>
**时长**: <可选>

## 讨论内容

### <议题 1>
- <要点>
- <要点>

### <议题 2>
- <要点>

## 决议

| # | 决议 | 说明 |
|---|------|------|
| 1 | <决议> | <详情> |
| 2 | <决议> | <详情> |

## 待办事项

| # | 负责人 | 任务 | 截止日期 | 优先级 |
|---|--------|------|----------|--------|
| 1 | @name | <任务> | YYYY-MM-DD | 高/中/低 |
| 2 | @name | <任务> | YYYY-MM-DD | 高/中/低 |

## 下次会议

- **时间**: <YYYY-MM-DD HH:mm>
- **议题**: <待确认议题>
```

### 编写规则

**DO**:
- ✅ 语言中立：如实记录，不添加个人观点
- ✅ 决议优先：将已确定的决策放在待讨论事项前面
- ✅ 行动项明确：每个任务都有负责人
- ✅ 保持原文的关键术语和缩写

**DON'T**:
- ❌ 添加未在会议中讨论的内容
- ❌ 模糊化不同意见（如实记录即可）
- ❌ 行动项没有负责人

## Step 4: 输出

直接输出完整的会议纪要供用户复制，同时提示：

```
如需保存为文件，我将写入 ./<会议主题>-<YYYY-MM-DD>.md
（在当前工作目录生成，文件名不含 meeting-notes/ 前缀以避免与技能目录混淆）
```

## Edge Cases

### 录音稿杂乱（语音转文字）
语音转文字文本通常包含：
- 重复词 → 清理，保留语义完整即可
- 填充词（"嗯"、"那个"、"就是"）→ 删除
- 断续语句 → 在不改变原意前提下连贯化
- 多人讲话混淆 → 尽量根据内容区分发言人

### 输入太简短
```
输入的文本较简短，只能提取以下信息：
<已提取信息>
建议补充更多会议内容以获得完整纪要。
```

### 无明确决策
```
本次会议似乎未形成明确决议，可能是信息同步或讨论性质的会议。
将主要以讨论要点形式记录。
```

### 技术讨论会议
对于架构评审、代码评审等技术会议，额外记录：
- **方案对比**：列出讨论过的方案及优缺点
- **技术决策**：选择的方案及理由
- **遗留问题**：待进一步调研的问题
