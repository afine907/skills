# 头脑风暴 — 三权分立决策技能

## Goal

将用户提出的问题或方案，通过模拟美国国会三权分立的机制，让三个独立角色分别思考和辩论，最终生成平衡、全面的决策建议。

## Trigger

- 用户说"头脑风暴"、"brainstorm"、"讨论方案"、"分析决策"
- 用户提出一个需要多角度思考的问题或方案
- 用户需要帮助做决策，希望看到不同立场的观点

## 角色定义

### 🏛️ 国会（立法权）— 方案构建者

**核心职责**：从用户需求出发，构建完整、可行的方案

**思考角度**：
- 用户价值：这个方案能解决什么问题？
- 完整性：方案是否覆盖了所有关键环节？
- 可行性：从技术/资源角度看是否可实现？
- 创新性：是否有更好的实现方式？

**输出**：
1. 方案的核心价值主张
2. 具体实施步骤
3. 预期收益
4. 初步的风险识别

### 🏢 总统（行政权）— 执行评估者

**核心职责**：评估方案的执行难度和实际效果

**思考角度**：
- 资源需求：需要多少人力、时间、成本？
- 执行障碍：有哪些潜在的阻碍和挑战？
- 优先级：这个方案在整体优先级中排第几？
- 替代方案：有没有更简单、更高效的替代方案？

**输出**：
1. 资源评估
2. 执行障碍分析
3. 替代方案建议
4. 风险缓解措施

### ⚖️ 法院（司法权）— 质量守护者

**核心职责**：评估方案的合规性、风险和长期影响

**思考角度**：
- 合规性：方案是否符合规范、标准、法律？
- 风险控制：有哪些潜在风险？如何规避？
- 长期影响：这个方案对系统/团队/产品有什么长期影响？
- 技术债务：是否会引入技术债务？

**输出**：
1. 合规性检查
2. 风险评估
3. 长期影响分析
4. 改进建议

## 工作流程

```
用户问题 → 角色分工 → 独立思考 → 辩论交锋 → 综合决策
```

### Step 1: 问题解析

从用户输入中提取：
- 核心问题/方案是什么？
- 关键约束条件（时间、资源、技术栈等）
- 期望目标（性能、成本、用户体验等）
- 任何隐含假设

### Step 2: 角色独立思考

同时启动三个 SubAgent，每个角色独立分析问题：

```
Agent({
  prompt: "你是一个{角色名}，负责{职责}。请从以下角度分析问题：\n\n{思考角度}\n\n问题：{用户问题}",
  label: "{角色名}"
})
```

每个 SubAgent 输出结构化分析报告。

### Step 3: 辩论交锋

三个角色针对彼此的观点进行辩论：

**国会**质疑总统：
- "你的替代方案真的能满足用户核心需求吗？"
- "这个简化会不会丢失关键功能？"

**总统**质疑国会：
- "你的方案太理想化，实际执行成本有多高？"
- "有没有考虑过资源限制？"

**法院**质疑两者：
- "这个方案的技术风险评估是否充分？"
- "长期维护成本考虑过吗？"

### Step 4: 综合决策

根据辩论结果，生成最终的方案对比表：

```markdown
# 决策报告

## 问题概述
{用户问题的简要描述}

## 方案对比表

| 维度 | 方案A（国会方案） | 方案B（总统方案） | 推荐 |
|------|------------------|------------------|------|
| 用户价值 | {评分} | {评分} | {推荐} |
| 执行难度 | {评分} | {评分} | {推荐} |
| 风险水平 | {评分} | {评分} | {推荐} |
| 长期影响 | {评分} | {评分} | {推荐} |
| 综合评分 | {总分} | {总分} | **{最终推荐}** |

## 各方观点

### 🏛️ 国会观点
{国会的核心论点}

### 🏢 总统观点
{总统的核心论点}

### ⚖️ 法院观点
{法院的核心论点}

## 最终建议

**推荐方案**：{推荐方案名称}

**理由**：
1. {理由1}
2. {理由2}
3. {理由3}

**实施要点**：
- {关键步骤1}
- {关键步骤2}
- {关键步骤3}

**风险提示**：
- {主要风险1}
- {主要风险2}
```

## 输出规范

### 评分标准

每个维度使用 1-5 分制：
- 1分：极差
- 2分：较差
- 3分：一般
- 4分：良好
- 5分：优秀

### 角色辩论格式

辩论时使用以下格式：

```
**{角色名}** 质疑：
> {质疑内容}

**{被质疑角色}** 回应：
> {回应内容}

**裁判**（综合分析）：
> {分析结论}
```

## 快速使用

```
# 技术方案选型
头脑风暴：应该用 React 还是 Vue 来重构前端？

# 产品决策
头脑风暴：是否要增加这个新功能？

# 架构设计
头脑风暴：微服务还是单体架构更适合这个项目？

# 代码重构
头脑风暴：如何重构这个模块？现有代码问题很多
```

## 注意事项

1. **角色独立性**：三个角色必须独立思考，不能互相影响初始分析
2. **辩论充分性**：每个质疑都必须有回应，不能跳过
3. **平衡性**：最终建议要平衡各方观点，不能偏袒某一方
4. **实用性**：方案必须考虑实际执行的可行性，不能太理想化
