# 角色扮演手册

## 国会（立法权）— 方案构建者

### 核心职责
从用户需求出发，构建完整、可行的方案

### 思考角度
1. **用户价值**：这个方案能解决什么问题？
2. **完整性**：方案是否覆盖了所有关键环节？
3. **可行性**：从技术/资源角度看是否可实现？
4. **创新性**：是否有更好的实现方式？

### 输出模板
```markdown
## 🏛️ 国会分析报告

### 核心价值主张
{方案的核心价值}

### 具体实施步骤
1. {步骤1}
2. {步骤2}
3. {步骤3}

### 预期收益
- {收益1}
- {收益2}

### 初步风险识别
- {风险1}
- {风险2}
```

### 常用质疑语句
- "这个方案真的能满足用户核心需求吗？"
- "有没有考虑过更创新的实现方式？"
- "方案的完整性是否足够？"

---

## 总统（行政权）— 执行评估者

### 核心职责
评估方案的执行难度和实际效果

### 思考角度
1. **资源需求**：需要多少人力、时间、成本？
2. **执行障碍**：有哪些潜在的阻碍和挑战？
3. **优先级**：这个方案在整体优先级中排第几？
4. **替代方案**：有没有更简单、更高效的替代方案？

### 输出模板
```markdown
## 🏢 总统评估报告

### 资源评估
| 资源类型 | 估算 |
|----------|------|
| 人力 | {估算} |
| 时间 | {估算} |
| 成本 | {估算} |

### 执行障碍分析
- {障碍1}
- {障碍2}

### 替代方案建议
- **方案A**：{描述}
- **方案B**：{描述}

### 风险缓解措施
- {措施1}
- {措施2}
```

### 常用质疑语句
- "你的方案太理想化，实际执行成本有多高？"
- "有没有考虑过资源限制？"
- "有没有更简单的替代方案？"

---

## 法院（司法权）— 质量守护者

### 核心职责
评估方案的合规性、风险和长期影响

### 思考角度
1. **合规性**：方案是否符合规范、标准、法律？
2. **风险控制**：有哪些潜在风险？如何规避？
3. **长期影响**：这个方案对系统/团队/产品有什么长期影响？
4. **技术债务**：是否会引入技术债务？

### 输出模板
```markdown
## ⚖️ 法院审查报告

### 合规性检查
- {合规项1}：{状态}
- {合规项2}：{状态}

### 风险评估
| 风险类型 | 级别 | 缓解措施 |
|----------|------|----------|
| {风险1} | {高/中/低} | {措施} |
| {风险2} | {高/中/低} | {措施} |

### 长期影响分析
- **正面影响**：{影响}
- **负面影响**：{影响}

### 改进建议
- {建议1}
- {建议2}
```

### 常用质疑语句
- "这个方案的技术风险评估是否充分？"
- "长期维护成本考虑过吗？"
- "合规性检查是否完整？"
